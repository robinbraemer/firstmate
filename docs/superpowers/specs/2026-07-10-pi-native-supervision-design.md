# Native Pi supervision design

## Scope

Pi primary and persistent-secondmate supervision uses one tracked project extension: `.pi/extensions/fm-primary-pi-watch.ts`.
The extension owns watcher arming, actionable wake delivery, re-arm, lifecycle cleanup, and the watcher-arm PreToolUse seatbelt.
Pi does not participate in the shared turn-end guard contract.
Ordinary Pi crewmates keep their existing per-task turn-end marker extension generated by `fm-spawn`.

## Runtime ownership

The existing bash watcher remains authoritative for polling, singleton ownership, durable wake queueing, and liveness beacons.
The Pi extension starts `bin/fm-watch-arm.sh --restart` as an owned detached process group and never implements watcher mechanics in TypeScript.
It uses one process-wide coordinator per resolved `FM_HOME` so same-path duplicate factories share one arm generation.
Each arm generation retains its own child, captured output, settlement state, and intentional-stop reason.
Only the current generation can clear coordinator state or inject an actionable wake.

The extension delegates every non-owned session-lock state to `bin/fm-lock.sh`, then re-checks ownership before spawning an arm.
The shell lock protocol remains the sole authority for stale PID identity, live other-owner refusal, and atomic acquisition.
Last-client shutdown cancels pending startup, waits for any lock claim, intentionally stops a raced arm, and removes the process-exit listener only after cleanup settles.

## Pi loading contract

Trusted project auto-discovery and explicit `-e` of the same canonical watcher path deduplicate to one extension registration.
A distinct copied watcher path conflicts on `fm_watch_arm_pi` and must fail startup.
Persistent Pi secondmates launch with one-run `--approve -e <home>/.pi/extensions/fm-primary-pi-watch.ts`.
The launch keeps project skills and settings available without requiring a saved trust decision.
No generated, global, daemon, socket, or background-job extension source participates in runtime supervision.

## Wake and lifecycle contract

The model arms with `fm_watch_arm_pi` or the human fallback `/fm-watch-arm-pi`.
The tool returns a normal Pi text result plus structured details.
An actionable watcher exit injects one `FIRSTMATE WATCHER WAKE` follow-up that instructs Pi to drain the durable queue and resume supervision.
Unexpected nonzero or signaled exits inject one failure follow-up.
Intentional reload, quit, process exit, or ownership transfer suppresses failure injection.
Reload must terminate the old arm and watcher, allow a new generation, and never inject a turn-end or false failure message.

The watcher extension also listens for Pi `tool_call` events.
For bash calls, it passes the exact command to `bin/fm-arm-pretool-check.sh --command` and blocks only on exit 2.
This preserves the shared watcher-arm seatbelt without a second Pi extension.

## Verification

Hermetic tests cover stale-lock recovery, non-harness PID reuse, live other-owner refusal, atomic lock racing, duplicate factories, stale callbacks, actionable and signaled exits, delayed-claim shutdown, process-exit cleanup, and the seatbelt wiring.
The strict TypeScript gate compiles only the tracked watcher extension against Pi 0.80.6 declarations and fails immediately when `tsc` fails.
The opt-in live test uses a fresh worktree-local lab, isolated Pi home, empty package inventory, dedicated tmux socket, and the single tracked watcher extension.
It checks same-path dedupe, distinct-copy conflict, one-run approval, native arm, actionable wake, drain and re-arm, reload without a false wake, and clean quit.
The external acceptance helper inventories only the watcher extension and rejects reload evidence containing a turn-end guard follow-up or false watcher failure.
